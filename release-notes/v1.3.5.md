# Yomite v1.3.5

Yomite v1.3.5 is a major reader and platform release. It rebuilds position tracking in the long-strip Webtoon reader, makes History resume the exact place you stopped reading, adds downloads for external sources, improves Cloudflare verification, and upgrades the app to Expo SDK 58 and React Native 0.88.

## Webtoon Reader

- Rebuilt long-strip page tracking around stable page identities instead of FlatList indexes. A page is now identified by its chapter and local page number, so appended chapters, recycled cells, and layout changes no longer corrupt the active page.
- Restoring a Webtoon from History now opens directly at the saved page and scroll offset. The reader no longer flashes page 1 and visibly scrolls through every page before reaching your position.
- Added predicted item layouts using cached image aspect ratios and measured page heights. Unrendered pages reserve realistic space, allowing the reader to seek directly into the chapter.
- Page measurements are cached across cell recycling. Images that scroll out of view and remount no longer collapse to a placeholder height and shift the rest of the chapter.
- If an image above the viewport finishes loading at a different height, the scroll position is compensated automatically to prevent visible drift and accidental page changes.
- Improved page-grid, slider, and jump navigation. Selecting a page now resolves the correct chapter and page even when the next chapter has already been appended to the strip.
- Added better handling for mode changes. Switching between single, double, and Webtoon modes preserves the page you were reading instead of snapping back to the start.
- The next chapter is preloaded when the reading line reaches the final three pages, so crossing a chapter boundary is smoother without loading the entire next chapter prematurely.
- History progress follows you into an appended next chapter and saves the correct chapter, page, and scroll offset when you return to History.
- Reduced scroll-position drift while images load, including during long chapters with mixed page heights.
- Improved Webtoon tap navigation and next/previous chapter behavior at the end of a chapter.

## Reading History

- History now restores both the saved page and the saved Webtoon scroll offset.
- Added an animated selection experience. Checkboxes slide and spring into place, row content shifts to make room, and inline actions fade and slide away.
- Replaced the old selection footer with an animated floating Delete bar that shows the selected count and respects the device safe area.
- The floating tab bar now hides while history items are selected, giving the selection controls more room.
- Added haptic feedback when entering and leaving selection mode.
- Refined the delete confirmation flow and several selection accessibility labels.

## Library

- Reduced the height of the Library category sheet and tightened its internal spacing.
- Reduced the category header, labels, descriptions, remove action, icon container, and icon sizes for a more compact one-handed layout.
- Preserved clear selected, unselected, and destructive states while making the sheet easier to scan.

## Sources and Verification

- Added a source classification registry based on the EverythingMoe directory. Catalog entries are now normalized as manga, manhwa, or mixed so category badges and filtering are more accurate.
- Added MangaDex Long Strip and Web Comic format tags to the available tag list.
- Added Cloudflare challenge detection for HTML, text, and response payloads so protected source responses produce a clear verification error instead of being parsed as empty pages.
- OniSaga now reports Cloudflare verification explicitly for catalog, search, details, and chapter requests instead of silently returning fallback data.
- Redesigned the in-app Cloudflare verification screen with a compact header, source name, helper strip, Verify action, and Done/Close controls.
- The verification flow now detects when the challenge page has been replaced by the target source, stores the clearing cookie, closes the sheet, and automatically retries the request.
- Added explicit domain handling for OniSaga and improved verification recovery for sources including ReiManga, Toonkotsu, WeebCentral, MangaDot, and related extensions.
- Added a reader banner when individual pages fail verification, with a direct Verify action and automatic image reload after the challenge is solved.
- Verification now also refreshes after returning from an external browser, making the retry flow more reliable on Android and iOS.

## Downloads

- Added chapter downloads for external sources, not just MangaDex.
- External chapter pages now use the source's required request headers, referer, user agent, and Cloudflare cookie when available.
- Browser downloads filter out headers that fetch is not allowed to set.
- Sanitized manga and chapter IDs when creating Android folder names, including IDs containing colons or reserved filesystem characters.
- Added legacy-folder cleanup so older downloads with unsafe folder names can still be removed.
- Internal metadata files are no longer added to the downloaded page list, preventing them from appearing as reader pages.
- Improved cleanup of downloaded files in both standard storage and Android Storage Access Framework folders.

## Notifications

- Improved Expo Go detection using Expo's runtime helper as well as execution environment and legacy ownership checks.
- Expo Go now loads local notification submodules directly, avoiding missing native module errors such as `ExpoTopicSubscriptionModule`.
- Local notifications can be scheduled in Expo Go while the app correctly falls back from unsupported remote push features.
- Standalone Android builds continue to use the full notifications module.

## Authentication and Dialogs

- Sign-in success toasts now use the reader's handle or display name instead of a generic provider message.
- The auth toast is positioned below the status bar or safe area, dismisses after a shorter delay, and uses a sign-out-specific icon and color.
- The web header now asks for confirmation before signing out instead of signing out immediately.
- Profile sign-out returns to the More tab before clearing the session.
- Login from the auth flow now returns to More instead of the removed standalone Profile destination.
- Redesigned the confirmation dialog with a Messenger-style elevated card in dark mode and a clean white card in light mode.
- Confirmation dialogs no longer use top icons or filled button pills. Titles and messages are left-aligned, actions are text-only and right-aligned, and buttons meet a 44pt minimum touch target.
- Updated call sites to rely on the simplified confirmation dialog instead of passing icon names.

## UI and Reliability

- Added a shared `AppRefreshControl` for consistent pull-to-refresh styling across Discover, Community, Library, and web layouts.
- Dark mode uses a white refresh circle with a dark spinner; light mode uses a black circle with a white spinner.
- Improved floating tab navigation with additional navigation and route fallbacks when the tab bar is rendered outside its usual navigator context.
- Added explicit `id` values to the root and tab navigators for more stable nested navigation.
- Updated text input and scroll view refs for React 19.3 typings.
- Moved the auth toast above the navigator so it can appear above reader and modal surfaces.
- Updated Cloudflare and error logging to avoid noisy console errors for expected verification challenges.

## Platform and Build

- Upgraded to Expo SDK 58, React Native 0.88, React 19.3, Reanimated 4.7, React Native Gesture Handler 3.3, React Native WebView 14, React Native View Shot 6, and TypeScript 6.
- Updated the Expo versioned documentation reference to SDK 58.
- Moved Android cleartext traffic configuration from the deprecated app config flag to a dedicated `withCleartextTraffic` config plugin.
- Added a postinstall compatibility patch for `react-native-view-shot` on React Native 0.88.
- Added support for the newer React Native ref and TurboModule behavior used by the upgraded stack.
- Android version code is now `10305`; app and package versions are `1.3.5`.

## Notes

- Remote push notifications are not supported inside Expo Go. Use a development build or production build to test push subscriptions.
- Some external sources may still require a successful Cloudflare challenge. Use the in-app verification flow when prompted.
- Web downloads remain subject to the source's CORS policy and browser header restrictions.
